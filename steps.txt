**********************************************************************************
PHASE 2: QUANTITATIVE SPINE: LINEAR PROBE accuracy
**********************************************************************************

1. Reuse AstroPT's own scripts/linear_probe.py pattern as your baseline reference
2. For each of your 3-4 selected model sizes: extract embeddings, train a simple linear classifier against each Galaxy Zoo label, record accuracy
3. Log every probe result (model size, layer, label, accuracy) to S3 as structured JSON — this becomes your first real chart, and your sanity check that everything downstream is measuring something real
4. This alone is a complete, defensible mini-result even if nothing else in the project worked — worth remembering under deadline pressure


Phase 3 — Activation capture across model sizes (Days 7–10)
Register forward hooks on AstroPT's transformer blocks — same methodology as your vlm_with_expert hooks in vla-grounding-probe, pointed at a new model family
For each size × hooked layer, run the eval subset through and capture activations
Stream activations to S3 (activations/) with a manifest JSON rather than holding them all locally — largest artifacts in the project, budget disk/bandwidth accordingly
Spot-check activation shapes and a couple of embeddings by hand before scaling up the full sweep, to avoid discovering a shape bug after a long run
Phase 4 — Mutual information estimation (Days 10–15) — the scientific core
Implement a kNN-based MI estimator (Kraskov-style; sklearn.feature_selection.mutual_info_regression/mutual_info_classif use this under the hood, or a dedicated package if you want more control) — committing to one estimator now, per our earlier discussion, rather than splitting time across two
Estimate I(activation; input) and I(activation; label) per layer per model size
Log every estimate with its exact config (estimator params, sample size, layer, size) to S3 (mi-results/) — full reproducibility, re-plottable without rerunning
Cross-check against Phase 2: does higher I(activation; label) track with higher probe accuracy? This is your estimator sanity check
Phase 5 — Analysis & honest reporting (Days 15–18)
Build the IB-plane trajectory plot: I(input) vs. I(label), tracked across model capacity, per layer
Report plainly whether a compression-like pattern emerges as capacity increases, is ambiguous, or doesn't appear — no overclaiming either direction
Write up the comparison against Phase 2's probe accuracy as the grounding result
If Phase 6 (training-axis stretch) doesn't happen, this is a complete, coherent project on its own
Phase 6 — Stretch: training-time trajectory (Days 18–21, only if ahead of schedule)
Configure AstroPT's own train.py with checkpoint_schedule=log, num_checkpoints=6-8, smallest model size, on a reduced data subset
Kick off training early enough in this window that you're not gambling the whole project on it finishing in time
If it completes: repeat Phases 3-5's methodology across these real training-step checkpoints as a second, complementary trajectory
If it doesn't finish in time: the capacity-axis result stands alone, and this becomes "future work" in your write-up — a legitimate, honest thing to say
