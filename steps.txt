**********************************************************************************
PHASE 2 - QUANTITATIVE SPINE: LINEAR PROBE ACCURACY
**********************************************************************************

1. Reuse AstroPT's own scripts/linear_probe.py pattern as the baseline reference
-> find AstroPT's actual embedding-extraction utility rather than reimplementing their tokenization (16×16 patches, spiral ordering, per-patch standardization) from scratch and risking a subtle mismatch with how the model was actually trained.
---> find .venv -iname "*.py" -path "*astropt*"

---> found the actual reference implementation — scripts/linear_probe.py, the real methodology. This tells us exactly how to preprocess and extract embeddings correctly:

1. Normalization: per-patch, along dim=1, (x - mean) / (std + 1e-8) — matches the paper's description exactly
2. Preprocessing wrapper: convert the image to a tensor, swap axes, run through galproc.process_galaxy (which internally patchifies, normalizes, and spiral-orders)
3. Embedding extraction: model.generate_embeddings(B)["images"] — but this only gives one embedding per model (final layer, mean-pooled), not per-layer. 
---> For our IB analysis we need every layer, so we'll replicate the block loop ourselves via hooks, same pattern as get_embeddings() internally, just capturing every step instead of only the last.

2. For each of the 3-4 selected model sizes: extract embeddings, train a simple linear classifier against each Galaxy Zoo label, record accuracy
-> scripts/09_linear_probe.py

3. Log every probe result (model size, layer, label, accuracy) to S3 as structured JSON
-> reults logged in probe-results/summary.json 

*** Headline finding: balanced accuracy increases with depth for four of five labels, in both models. 
---> smooth, disc, artefact, and tight_spiral all show a fairly consistent upward trend from layer 0 to the final layer — e.g. in 095M, smooth climbs from 0.593 (barely above chance) at layer 0 to 0.730 at layer 10, and artefact climbs from 0.781 to 0.916 by the final layer. 
---> That's exactly the kind of depth-wise representation-refinement signal we hope to see, and it's a real, quantitative, defensible result on its own — this is our guaranteed floor from Phase 2, and it delivered.

*** The interesting anomaly: edge_on never rises above chance in either model. 
---> Every single layer, both sizes, balanced accuracy for edge_on sits in the 0.48-0.58 range — statistically indistinguishable from a coin flip, and in a couple of layers (015M layer 3: 0.494; 095M layer 4: 0.483) it dips below 0.5, 
---> meaning a linear probe does no better than random guessing at recovering edge-on orientation from these representations, at any depth. 
---> Treating as a genuine finding, not a bug to fix — four labels show the expected learning curve, one doesn't, and that's a real, reportable contrast. 
---> Possible explanations worth stating honestly rather than picking one: edge-on-ness may require non-linear features a linear probe can't extract even if the model encodes them; or, at 2.8% prevalence, even 3000 samples may leave the probe under-constrained for this specific label.

*** Capacity comparison, more tentative: 095M's peak balanced accuracy per label is generally a bit higher than 015M's peak (e.g. smooth: 0.692 vs 0.730; disc: 0.702 vs 0.727) 
-> consistent with capacity helping, but the gap is modest enough that I am not including this in the findings
-> Worth mentioning as a secondary observation, not a headline claim.

*********************************************************************************
PHASE 3 — ACTIVATION CAPTURE ACROSS MODELS
*********************************************************************************

1. Register forward hooks on AstroPT's transformer blocks
2. For each size × hooked layer, run the eval subset through and capture activations
3. Stream activations to S3 (activations/) with a manifest JSON rather than holding them all locally — largest artifacts in the project, budget disk/bandwidth accordingly
4. Spot-check activation shapes and a couple of embeddings by hand before scaling up the full sweep, to avoid discovering a shape bug after a long run

-> all steps covered under Phase 2
-> get_all_layer_embeddings() in the script we ran: it manually replicates AstroPT's own block-iteration loop (for block in model.transformer.h: x = block(x)) and captures x.mean(dim=1) after every single layer
-> that's activation capture, just done by directly looping over the exposed model.transformer.h ModuleList rather than using PyTorch's formal register_forward_hook() API. 
-> Same result (every layer's activations, for every image, for both sizes), different mechanism. 
-> Registering formal hooks would have been necessary if we needed to intercept activations without modifying the forward pass or without direct access to intermediate layers
-> but since AstroPT's transformer.h is just a plain, iterable ModuleList, looping over it ourselves was simpler and gave us the same data with less code.
